# tempo-zk-utils

Utilities to support **Nori Bridge** on Tempo: the SP1 program identifier the bridge contract verifies against, and decoding of the bridge head's SP1 Groth16 consensus MPT proofs.

## Integrity

The bridge contract (`NoriTempoTokenBridge`) accepts proofs for one SP1 program vkey, `bridgeHeadNoriSP1HeliosProgramVk`, stored in [`src/integrity/nori-sp1-helios-program.vk.json`](./src/integrity/nori-sp1-helios-program.vk.json): a copy of [`nori-elf/nori-sp1-helios-program.vk.json`](https://github.com/Nori-zk/nori-bridge-head/blob/develop/nori-elf/nori-sp1-helios-program.vk.json) from [bridge-head](https://github.com/Nori-zk/nori-bridge-head). It changes whenever the Helios light client program changes. When bridge-head releases a new version, copy `nori-elf/nori-sp1-helios-program.vk.json` from the appropriate release tag into [`src/integrity/nori-sp1-helios-program.vk.json`](./src/integrity/nori-sp1-helios-program.vk.json) and commit it, along with new example proofs made by that program (see [Test examples](#test-examples)).

It is the proofs' first Groth16 public input (`proof.Groth16.public_inputs[0]`) as 32 bytes, which is what the SP1 verifier contract takes as `programVKey`.

```typescript
import { bridgeHeadNoriSP1HeliosProgramVk } from '@nori-zk/tempo-zk-utils';
```

## Proof decoding

The bridge head's proofs are `SP1ProofWithPublicValues` JSON (`NoriSP1ProofInput` from `@nori-zk/pts-types`). Their public values are the guest's `ProofOutputs`: 220 bytes at fixed big-endian offsets.

```typescript
import {
    decodeConsensusMptProof,
    extractEthProofQueueAddressFromSP1Proof,
    sp1Groth16ProofBytes,
    sp1ProgramVkey,
    sp1PublicValues,
} from '@nori-zk/tempo-zk-utils';

const outputs = decodeConsensusMptProof(proof);
// outputs.inputSlot, outputs.outputStoreHash, outputs.verifiedRequestsRoot, outputs.outputQueueCursor, ...

// The arguments of NoriTempoTokenBridge.update(proof, sp1PublicInputs):
const proofBytes = sp1Groth16ProofBytes(proof); // the verifier selector, then the encoded proof (356 bytes)
const publicValues = sp1PublicValues(proof); // the 220-byte ProofOutputs
```

| Function | Returns |
| --- | --- |
| `decodeConsensusMptProof(proof)` | The decoded `ProofOutputs`: slots, cursors and block number as `bigint`, hashes and the queue address as hex. Throws unless the public values are exactly 220 bytes |
| `extractEthProofQueueAddressFromSP1Proof(proof)` | The `NoriProofRequestQueue` address the proof anchors its storage witnesses on |
| `sp1Groth16ProofBytes(proof)` | The proof bytes the SP1 Groth16 verifier contract takes: the first 4 bytes of the Groth16 vkey hash (the verifier selector), then the encoded proof |
| `sp1PublicValues(proof)` | The proof's public values |
| `sp1ProgramVkey(proof)` | The SP1 program vkey the proof was made for |

## Test examples

[`src/test-examples/sp1-mpt-proof/`](./src/test-examples/sp1-mpt-proof/) holds the first SP1 Groth16 proof of the integration test data, made by the program in [Integrity](#integrity), and `sp1ProofMessage.ts` exports it as `sp1ConsensusMPTGroth16Proof`. The tests check that it was made for that vkey and that it gives the verifier's proof bytes and public values.

The integration test data is made by running the bridge head for four cycles against an Ethereum `NoriProofRequestQueue` that accepts no locks or proof requests, so every example proof drains no requests: its input and output queue cursors are 0. Tests that need requests plant them on top.

## Test vectors

[`src/test-vectors/proof-request-queue/`](./src/test-vectors/proof-request-queue/) is a copy of bridge-head's `test-vectors/proof-request-queue/`, generated by the Rust side: request leaves, the `ProofOutputs` encoding, and the queue's storage locations. The tests check `decodeConsensusMptProof` against the `ProofOutputs` vectors. Refresh the copy whenever bridge-head regenerates them.
